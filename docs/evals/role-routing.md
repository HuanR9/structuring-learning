# 岗位路由静态验收案例

本文件用于检查 `SKILL.md`、`references/core/role-routing.md` 与行业情境索引的一致性。它是静态验收清单，不代表真实 Agent 已按预期自动路由，也不替代学习者验证。

| ID | 用户请求 | 预期入口与路由 | 不应发生 |
|---|---|---|---|
| RR-01 | “我准备转 SRE，做过 Linux 运维，想能独立处理线上故障。” | 岗位入口；核心为 `references/domains/ops/sre.md`，按目标补系统运维等前置模块。 | 不展开全部运维、安全和研发模块；不重复追问已提供的基础。 |
| RR-02 | “每月要给部门做预算差异和现金流分析，想把结论讲清楚。” | 任务入口；以 `references/domains/finance/financial-analysis.md` 为主，按分析所需关联会计模块。 | 不强行指定 FP&A 岗位；不直接给投资建议。 |
| RR-03 | “帮我系统学会计基础，不针对具体岗位。” | 专业领域入口；按 `references/domains/finance/_index.md` 路由到 `references/domains/finance/accounting.md`。 | 不加载岗位路由作为必经步骤；不追问目标岗位。 |
| RR-04 | “我想做教师，重点提升课堂提问、反馈和评估。” | 教师岗位入口；核心为 `references/domains/education/teaching-assessment.md`。 | 不把教学设计师当同一目标；不默认展开整套课程设计。 |
| RR-05 | “我想转教学设计师，主要负责企业课程开发。” | 教学设计师岗位入口；核心为 `references/domains/education/instructional-design.md`，按企业人才发展任务关联 `references/domains/people/people-development.md`。 | 不以课堂教师模块为默认核心；不把两个岗位合成一个模糊路线。 |
| RR-06 | “我想提升做数据的能力。” | 任务/能力入口；先询问一个能区分目标的聚焦问题（例如工作对象或想完成的分析任务），或在合理假设下给出可调整路线。 | 不虚构目标岗位；不无条件加载整个数据、财务和产品模块。 |
| RR-07 | “我想做制造业生产数据分析师，关注设备停机和质量数据。” | 岗位 + 行业入口；核心为 `references/domains/product/data.md`，再加载 `references/industries/manufacturing.md`，仅裁剪停机/质量相关内容。 | 不将场景扩成全量 OT 安全或制造工程培训；不默认适用美国规范或任何单一指标口径。 |
| RR-08 | “我们有一份岗位说明书，帮我按它做转岗学习路线。” | 岗位入口；提取说明书明确要求，映射相关模块，并区分原文要求与推断。 | 不把招聘描述推断成行业通用标准；不把敏感岗位材料写入外部状态文件全文。 |

## 走查结果记录

本轮按表中预期逐项核对路由规则和目标文件：

| 案例 | 静态走查 | 依据 |
|---|---|---|
| RR-01 | 通过 | 岗位核心为 SRE 模块，系统运维按故障处理目标裁剪。 |
| RR-02 | 通过 | 具体任务直接路由财务分析，没有强行命名岗位。 |
| RR-03 | 通过 | 明确领域学习直接进入会计模块，不要求岗位入口。 |
| RR-04 | 通过 | 教师路由到教学与评估模块。 |
| RR-05 | 通过 | 教学设计师路由到教学设计模块，企业培训协作项有任务条件。 |
| RR-06 | 通过 | 模糊能力需求先澄清关键目标，或在合理假设下给出可调整路线。 |
| RR-07 | 通过 | 生产数据分析以数据分析为核心，制造业情境只增补相关节点。 |
| RR-08 | 通过 | 用户提供的岗位说明书优先，并区分原文要求与推断。 |

以上仅为文档规则的人工静态走查；真实 Agent 是否能稳定识别入口和执行路由，仍需在目标运行环境中单独验证。
