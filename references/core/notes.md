# 结构化笔记规范（P4 专用）

## 基本原则

- 笔记是**用户的学习产出**，agent 提供骨架与引导问题，用户填充内容；用户要求代写时，代写内容必须用引用块标注并提醒用户用自己的话改写。
- 一个学习模块对应一个笔记文件：`notes/<两位序号>-<模块slug>.md`，用 `templates/note-module.md` 模板。
- **序号规则**：序号 = `roadmap.md` 模块表的 `#` 列，两位补零（01、02…）。文件在访达/Obsidian 中即按学习顺序排列，不用前后翻找。
- **重排联动**：复盘回写导致模块表重排时，序号随之重编号——同步重命名笔记文件并更新所有 `[[notes/...]]` 链接；这是重操作，执行前必须告知用户。
- 全部使用纯 Markdown，兼容 Obsidian。

## 笔记结构（每模块固定段落）

1. **是什么**：一句话定义（用户自己的话，禁止抄书）。
2. **为什么**：它解决什么问题，在知识树中的位置与上下游。
3. **怎么做**：核心操作/机制/推导，配例子。
4. **坑与误区**：学习中实际踩到的，而非泛泛而谈。
5. **自测**：3 个以内的问题，能答出即过关（对照"掌握证据"）。
6. **关联**：用 `[[双链]]` 链接相关模块笔记，构建知识网。

## Obsidian 兼容约定

- 每个笔记文件带 YAML frontmatter：`domain`（领域）、`module`（模块）、`status`（learning/done/review）、`created`、`review_due`（下次复习日期）。
- 标签规范：`#learning/<领域>/<层>`，如 `#learning/dba/L2`。
- 双链优先链向同领域笔记；跨领域链接需在笔记末尾"关联"节说明原因。

## 填充节奏

- 学习新模块前先打开骨架，带着"自测"问题学。
- 学完立即填充"是什么/为什么/怎么做"三节；"坑与误区"允许后续遇到再补。
- 填充完成且自测通过后，将 frontmatter `status` 改为 `done`，并更新 `roadmap.md`。
