# 通用工作流程（P0–P5）

> 领域无关的主流程。领域特有的知识骨架、信源、检查点见 `references/domains/` 下对应模块。

## P0 锚定（阻塞：未完成不得进入 P1）

通过提问确认以下信息，写入 `profile.md`（用 `templates/domain-profile.md` 模板）：

1. **领域与细分**：学什么？路由到哪个领域模块？
2. **目标层级**：了解（能聊）/ 能用（能干活）/ 精通（能排障与取舍）？三选一，不接受"都学"。
3. **现有基础**：零基础和"用过但不系统"的路径完全不同，必须问清。
4. **时间预算**：每天/每周可投入时长，期望达成时间。
5. **材料约束**：是否有指定教材、内部文档、考试目标？

规则：一次最多问 3 个问题，优先问最关键的（领域、目标、基础）；用户答不全时给出合理默认值并标注【假设】。

## P1 调研

1. 先查领域模块的"权威信源清单"，按分级取用：官方文档 > 经典书籍 > 高质量社区。
2. 需要联网核实时用搜索工具验证信源时效性（版本、是否停更）。
3. 产出骨架候选：若领域模块有"预设知识骨架"，以其为起点裁剪；无则自建后提示用户沉淀为该领域模块。
4. 调研发现记入 `research-notes.md`（信源 + 一句话可信度备注），禁止无来源编造结构。

## P2 建模（阻塞：未经用户确认不得进入 P3）

1. 按 `references/core/modeling.md` 的决策树选择结构模式。
2. 生成知识地图写入 `knowledge-map.md`（用 `templates/knowledge-map.md` 模板）。
3. **必须向用户展示完整结构并等待确认**；用户提出增删改后迭代，直至明确认可。

## P3 路径

1. 将知识地图节点转为学习模块，标注依赖关系（前置模块）。
2. 按"基础→核心→进阶"排序，设置里程碑（每层一个）与检查点（能力证据，非考试题）。
3. 结合 `profile.md` 的时间预算给出排期建议（按周粒度，不排具体到小时的日程）。
4. 写入 `roadmap.md`（用 `templates/roadmap.md` 模板）。

## P4 笔记

1. 按 `references/core/notes.md` 规范为每个学习模块生成笔记骨架（`notes/` 目录）。
2. 学习过程中逐模块填充；笔记是用户的学习产出，不是替你生成教程。
3. 用户学完一个模块，更新 `roadmap.md` 中该模块状态（🔲→✅）。

## P5 复盘

按 `references/core/review.md` 执行：间隔复习提醒、薄弱点标记、结构回写。复盘结论追加到 `review-log.md`（追加写，不覆盖）。

## 续学恢复（新会话入口）

用户提到继续学习某领域时：

1. 读取 `./learning/<slug>/profile.md` 与 `roadmap.md`；
2. 展示进度摘要：目标层级 / 模块完成度（✅x/N）/ 当前模块 / 待复习项；
3. 询问继续当前模块还是进入下一模块，不要自作主张推进。
