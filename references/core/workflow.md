# 通用工作流程（P0–P5）

> 领域无关的主流程。领域特有的知识骨架、信源、检查点见 `references/domains/` 下对应模块。

## P0 锚定（必要信息未明确时阻塞 P1）

优先用一轮（最多 3 个问题）确认决定学习结构的关键信息，写入 `profile.md`（用 `templates/domain-profile.md` 模板）：

1. **领域与细分**：学什么？路由到哪个领域模块？
2. **目标能力**：学完后希望能解释、完成哪些任务或独立处理哪些问题？可用“了解 / 能用 / 精通”作简写，但要落到可观察的结果。
3. **现有基础**：零基础和"用过但不系统"的路径差异较大，应优先确认。

只有领域或目标能力会实质改变结构、且无法合理假设时，P0 才阻塞后续阶段。基础不明可暂按零基础并标注【假设】；时间预算、期望日期和材料约束仅在会改变排期或信源时追问，缺省时不估算周期。涉及法律、监管政策或其他强辖区差异内容时，确认适用国家/地区；无法确认时标注假设并避免给出适用性结论。每轮最多问 3 个问题；用户答不全时用明确标注的假设继续，不反复追问同一信息。

## P1 调研

1. 先查领域模块的信源清单和用户提供的材料；按问题需要选择官方文档、经典书籍或高质量社区，不为了填满流程而泛搜。
2. 对时效敏感、高风险、陌生或存在争议的主张，核验一手来源及适用范围；无法访问或无法确认时明确标注，不把推测写成事实。
3. 产出骨架候选：有预设骨架时以其为起点，结合目标能力裁剪；无则自建并提示用户可沉淀为领域模块。
4. 实际查证过的来源按 `templates/research-notes.md` 记入 `research-notes.md`；未开展外部调研时不创建空记录，也不声称已核实。

## P2 建模（默认确认后进入 P3）

1. 按 `references/core/modeling.md` 的决策树选择结构模式。
2. 生成知识地图写入 `knowledge-map.md`（用 `templates/knowledge-map.md` 模板）。
3. 向用户展示结构草案、关键假设和主要取舍。默认等待用户确认或修改后再进入 P3；若用户明确要求直接完成整套路线/产出，视为允许按合理假设继续，说明草案仍可调整，不再额外等待一次确认。

## P3 路径

1. 将知识地图节点转为学习模块，标注依赖关系（前置模块）。
2. 按"基础→核心→进阶"排序，设置里程碑（每层一个）与检查点（能力证据，非考试题）。
3. 有时间预算时结合 `profile.md` 给出按周粒度的排期建议，不排具体到小时；没有预算时先给模块顺序和里程碑，不估算周期。
4. 写入 `roadmap.md`（用 `templates/roadmap.md` 模板）。

## P4 笔记

1. 按 `references/core/notes.md` 规范为路线中保留的学习模块生成笔记骨架（`notes/` 目录）；不必为标注为暂不学或跳过的节点生成笔记。
2. 学习过程中逐模块填充；笔记是用户的学习产出，不是替你生成教程。
3. 开始学习时将状态从 `🔲` 改为 `🔵`；完成掌握证据并通过自测后，从 `🔵` 改为 `✅`，同步更新笔记状态。

## P5 复盘

按 `references/core/review.md` 执行：间隔复习提醒、薄弱点标记、结构回写。复盘结论追加到 `review-log.md`（追加写，不覆盖）。

## 续学恢复（新会话入口）

用户提到继续学习某领域时：

1. 在 `./learning/` 下查找同时含 `profile.md` 与 `roadmap.md` 的领域目录，读取档案中的 `domain` 与 `subdomain` 做匹配；目录名 slug 作为辅助信息，不单凭目录名猜领域。
2. 只有一个匹配目录时读取其 `profile.md` 与 `roadmap.md`。有多个匹配时展示目录名并请用户选择；没有匹配时询问要续学的领域或 slug，再按 P0 规则启动，不创建同名副本。
3. 匹配目录缺少必需文件或 frontmatter 无法读取时，说明具体缺失并暂停进度恢复；不要自动覆盖或重建已有目录。
4. 展示进度摘要：目标层级 / 模块完成度（✅x/N）/ 当前模块 / 待复习项；同时扫描已过期的 `review_due`。
5. 询问继续当前模块还是进入下一模块，不要自作主张推进。
