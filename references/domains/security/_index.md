# 安全类领域模块（security）

## 领域画像

安全类关注识别、降低和响应信息系统风险，覆盖软件构建、云与平台配置、持续监测和事件处置。它与研发、运维、法律合规相交，但主问题是“如何预防、发现和应对安全威胁”。

- 用户只说“网络安全”或“信息安全”时，先展示三条细分主线并询问其目标；若目标明确，直接选主模块并关联必要前置。
- 边界提示：系统运维/网络运维/云原生关注可用性与交付，安全模块关注威胁、控制与风险；法律数据合规关注法定义务和合规流程，安全类不替代法律意见。
- 实践原则：只在授权的靶场、隔离环境或桌面推演中验证；不得把生产系统或未授权目标作为练习场。高影响操作先做范围、回滚和授权确认。

## 通用信源（安全类共享）

- 标准与框架：NIST Cybersecurity Framework 2.0；结合目标岗位与司法辖区选择控制框架，不把框架清单误当成合规认证。
- 官方技术指南：OWASP 项目文档、CISA 指南、云服务商与平台官方安全文档；安全建议需核对版本与适用环境。
- 威胁知识：MITRE ATT&CK 用于描述对手行为和映射检测思路，不当作漏洞分类或完整风险框架。
- 实践证据：威胁模型、配置审查、靶场测试报告、检测规则与事件桌面推演；不得以“扫描无告警”证明系统安全。
