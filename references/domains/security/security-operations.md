# 安全运营与事件响应细分模块

> 领域模块六节 Schema：领域画像 / 细分路由 / 预设知识骨架 / 权威信源清单 / 进阶检查点 / 常见误区。

## ① 领域画像

安全运营与事件响应关注把资产、日志、威胁情报、检测规则和响应流程连成持续运行的防护能力。学习主线是准备、监测、分诊、遏制、恢复与复盘。练习以脱敏样例、靶场或桌面推演为主，不执行未授权监测或生产处置。

## ② 细分路由

用户目标若聚焦漏洞开发与修复，转应用安全；若聚焦云账户和集群配置，转云与容器安全；若聚焦业务连续性或常规服务故障，关联 SRE。真实事件中的法律报告、隐私通知和取证要求需按司法辖区咨询合格专业人士。

## ③ 预设知识骨架

建模（P2）以此树为起点，按用户目标层级裁剪（规则见 `references/core/modeling.md`）。每个叶子节点括注掌握证据。

```
安全运营与事件响应
├── L1 运营基础
│   ├── 资产、风险与职责（资产重要性、威胁场景、升级职责；能为样例组织建立最小资产清单并标注责任人和关键依赖）
│   ├── 安全事件分类（事件、告警、漏洞、影响范围；能用给定案例区分误报、可疑活动和已确认事件并说明依据）
│   └── 日志与数据治理（日志来源、时间同步、访问权限、保留与脱敏；能为一条检测用例列出必需日志并审查隐私与保留风险）
├── L2 监测与检测
│   ├── 威胁情报与行为框架（情报可信度、TTP、MITRE ATT&CK 映射；能把模拟行为映射到 ATT&CK 技术并注明证据和映射局限）
│   ├── 告警分诊与关联（严重度、上下文、资产关键性、误报；能按明确标准分诊一组模拟告警并解释优先级与升级理由）
│   └── 检测工程（假设、数据源、规则、测试、调优；能编写一条基于样例日志的检测规则并用正反样例评估效果）
├── L3 事件响应
│   ├── 准备与响应计划（角色、联系链、授权、工具和演练；能为一个模拟场景写出响应分工、决策权限和升级路径）
│   ├── 分析与遏制（范围界定、证据保全、隔离选择、业务影响；能在桌面推演中形成有依据的遏制方案并记录证据缺口）
│   └── 根除与恢复（凭证轮换、系统恢复、验证观察；能为模拟入侵制定恢复检查表并定义安全恢复的退出条件）
└── L4 改进与治理
    ├── 复盘与改进（根因、控制失效、行动项、验证；能撰写无责复盘并将改进项关联到责任人、期限和验证证据）
    ├── 演练与指标（桌面推演、检测覆盖、响应时间口径；能设计一个演练目标和评分标准，并解释指标限制）
    └── 服务与外部协作（SOC/SIEM/托管检测的职责与交接；能评估一份样例服务边界并列出关键数据、响应和升级约定）
```

## ④ 权威信源清单

| 级别 | 信源 | 备注 |
|---|---|---|
| 政府标准 | [NIST SP 800-61 Rev. 3](https://csrc.nist.gov/pubs/sp/800/61/r3/final) | 2025 年发布，取代 Rev. 2；学习事件响应时以当前版本为准 |
| 政府框架 | [NIST Cybersecurity Framework 2.0](https://www.nist.gov/cyberframework) | 用于风险管理结果和组织改进，不代替具体响应流程 |
| 威胁知识 | [MITRE ATT&CK](https://attack.mitre.org/) | 对手行为知识库，映射需附证据，不将技术映射误认为归因结论 |
| 政府指南 | [CISA Cybersecurity Advisories](https://www.cisa.gov/news-events/cybersecurity-advisories) | 当前威胁和处置建议；核实适用系统及公告日期 |
| 实践 | 授权靶场、脱敏日志和桌面推演材料 | 保护真实个人信息与敏感业务数据；生产事件依正式响应机制处理 |

## ⑤ 进阶检查点

| 阶段 | 能力证据（能做成这些即过关） |
|---|---|
| 初级（L1） | 基于模拟日志分辨告警与事件，说明资产背景和判断依据 |
| 中级（L2–L3） | 为模拟威胁构建检测规则并完成桌面响应推演，保留决策与证据记录 |
| 高级（L4） | 主持一次桌面演练和无责复盘，提出可追踪、可验证的改进项 |

## ⑥ 常见误区

1. **把告警数量当作安全水平**：告警多可能代表噪声，告警少也可能代表可见性不足。
2. **未验证情报就归因**：行为映射和情报线索只能支持假设，不能单独证明攻击者身份。
3. **先清理再保全证据**：遏制和证据保全需按授权、业务影响和响应计划权衡并记录理由。
4. **把响应计划当静态文档**：联系人、权限、系统依赖和供应商流程要通过演练更新。
5. **忽视司法辖区要求**：报告时限、证据处理和通知义务需由适格法律/隐私专业人士确认。
