# 云与容器安全细分模块

> 领域模块六节 Schema：领域画像 / 细分路由 / 预设知识骨架 / 权威信源清单 / 进阶检查点 / 常见误区。

## ① 领域画像

云与容器安全关注云上工作负载、身份、网络、数据和容器平台的安全控制，重点理解责任边界、配置风险、检测能力与恢复准备。学习按用户实际云厂商和平台裁剪，避免把某一家云的产品名当作通用原理。

## ② 细分路由

本模块聚焦云控制面、云上工作负载和容器/Kubernetes 安全配置。云原生模块负责集群交付与日常运行机制；系统/网络运维负责主机与连通性；安全模块负责威胁建模、权限边界、加固、检测与安全审查。

## ③ 预设知识骨架

建模（P2）以此树为起点，按用户目标层级裁剪（规则见 `references/core/modeling.md`）。每个叶子节点括注掌握证据。

```
云与容器安全
├── L1 云安全基础
│   ├── 共享责任与信任边界（云服务模型、账户/项目/租户边界；能为一个工作负载划分云厂商与客户责任并标注责任交接点）
│   ├── 云资产与威胁面（资产清单、暴露面、数据流；能根据样例架构列出关键资产、外网入口和高价值身份）
│   └── 身份与权限治理（IAM、最小权限、短期凭证、角色分离；能审计一组示例策略并提出可验证的权限收敛方案）
├── L2 云工作负载控制
│   ├── 网络隔离与边界（子网、安全组、防火墙、私有服务；能为样例架构绘制访问路径并验证默认拒绝与必要放行规则）
│   ├── 数据与密钥保护（静态/传输加密、密钥轮换、秘密存储；能为样例数据流选定保护控制并指出密钥权限和恢复依赖）
│   └── 配置与审计（安全基线、配置漂移、控制面日志；能对沙箱账户执行只读配置审查并提交风险与修复优先级）
├── L3 容器与集群安全
│   ├── 镜像与供应链（基础镜像、依赖来源、签名与漏洞管理；能检查一个示例镜像构建流程并提出可验证的来源与更新控制）
│   ├── Kubernetes 权限与隔离（RBAC、ServiceAccount、网络策略、准入控制；能审查隔离集群配置并验证工作负载最小权限）
│   └── 运行时与秘密管理（容器权限、只读文件系统、秘密挂载、运行时信号；能在本地集群加固一个工作负载并验证权限和秘密暴露面）
└── L4 持续检测与响应
    ├── 云安全态势管理（基线、持续合规检查、风险例外；能定义适用基线并为样例违规配置分级和跟踪整改）
    ├── 云日志与告警（控制面审计、工作负载信号、告警路由；能用模拟日志构建一条检测规则并验证告警上下文足以支持分诊）
    └── 云事件处置与恢复（凭证泄露、公开存储、异常工作负载；能用桌面推演写出隔离、证据保全、恢复和复盘步骤）
```

## ④ 权威信源清单

| 级别 | 信源 | 备注 |
|---|---|---|
| 官方框架 | [NIST Cybersecurity Framework 2.0](https://www.nist.gov/cyberframework) | 风险治理和结果分类；需结合组织与适用法规裁剪 |
| 官方框架 | [AWS Well-Architected Security Pillar](https://docs.aws.amazon.com/wellarchitected/latest/security-pillar/welcome.html) | AWS 专项参考；不要将其控制项直接当成多云通用实现 |
| 官方文档 | 实际使用的云服务商安全、身份与审计文档 | 按云厂商、区域、服务和版本核对 |
| 官方文档 | [Kubernetes Security Checklist](https://kubernetes.io/docs/concepts/security/security-checklist/) | Kubernetes 通用安全检查入口；结合发行版和托管服务边界 |
| 官方项目 | [OWASP Kubernetes Top 10](https://owasp.org/www-project-kubernetes-top-ten/) | 风险意识与容器编排安全背景，结合官方平台文档验证 |

## ⑤ 进阶检查点

| 阶段 | 能力证据（能做成这些即过关） |
|---|---|
| 初级（L1） | 解释样例云架构的责任边界，绘制资产、身份和外网暴露面 |
| 中级（L2–L3） | 在沙箱账户或本地集群完成权限与配置审查，提交加固前后验证记录 |
| 高级（L4） | 对模拟云安全事件完成桌面推演，说明告警依据、隔离范围、证据保全和恢复条件 |

## ⑥ 常见误区

1. **以为云厂商负责所有安全**：云厂商与客户责任随服务模型变化，必须逐服务确认。
2. **把安全组或网络隔离当成完整安全**：身份、数据、构建链、运行时和审计仍需独立控制。
3. **用生产环境练习高风险配置**：先使用沙箱账户或本地集群，真实环境变更必须遵循授权、回滚和变更流程。
4. **只扫镜像不管来源**：漏洞扫描不能证明依赖可信、构建过程安全或部署策略正确。
5. **把合规通过等同于安全**：基线检查提供风险信号，不代表没有未知威胁或业务逻辑漏洞。
