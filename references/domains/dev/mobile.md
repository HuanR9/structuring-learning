# 移动研发细分模块

> 领域模块六节 Schema：领域画像 / 细分路由 / 预设知识骨架 / 权威信源清单 / 进阶检查点 / 常见误区。

## ① 领域画像

移动研发负责 iOS / Android / 跨平台客户端的开发：界面、数据、性能、发布。核心价值是**"在受限设备上交付流畅体验"**——内存、电量、弱网、碎片化是移动端的四大现实约束。

## ② 细分路由

本模块即最小细分单位，不再下分。平台选择（原生 vs 跨平台）作为 L1 的决策变量处理。

## ③ 预设知识骨架

建模（P2）以此树为起点，按用户目标层级裁剪（规则见 `references/core/modeling.md`）。每个叶子节点括注掌握证据。

```
移动研发
├── L1 语言与平台基础
│   ├── 平台选型（原生 iOS/Android vs Flutter/RN：按团队与场景决策）
│   ├── 开发语言（Swift / Kotlin / Dart 选一，能写惯用法代码）
│   └── 平台规范（HIG / Material Design：导航、手势、返回逻辑）【时效敏感】
├── L2 UI 层
│   ├── 页面布局与组件（约束/声明式 UI，能还原设计稿）
│   ├── 列表与图片（复用机制、大图加载，这是性能主战场）
│   └── 动画与手势（转场、弹性动画、手势冲突处理）
├── L3 数据与网络
│   ├── 本地存储（SQLite/KeyChain/MMKV/DataStore 的选型）
│   ├── 网络层（HTTP 封装、长连接、弱网策略与重试）
│   └── 缓存与数据同步（多级缓存、离线策略）
├── L4 发布与质量
│   ├── 打包与签名（证书/描述文件/应用市场审核要求）
│   ├── 崩溃与性能监控（崩溃率、启动耗时、卡顿采集）
│   └── 灰度与热修复（合规边界内的更新策略）【时效敏感】
└── L5 专项层（可选分支）
    ├── 推送与隐私合规（权限申请、隐私清单）
    ├── 跨平台框架深入（Flutter/RN 的渲染机制与边界）
    └── 音视频与地图等 SDK 集成
```

## ⑤ 进阶检查点

| 阶段 | 能力证据（能做成这些即过关） |
|---|---|
| 初级（L1–L2） | 完成一个含网络请求与长列表的页面并在真机流畅运行；讲清一次页面从创建到销毁的生命周期 |
| 中级（L3–L4） | 独立负责一个模块（本地存储+缓存+弱网策略）；用工具定位一次内存泄漏或启动耗时问题 |
| 高级（L5） | 设计客户端的整体架构（分层、模块化）；主导一次崩溃治理或性能专项 |

## ⑥ 常见误区

1. **生命周期不清**：页面/组件生命周期没搞懂，泄漏与空指针是迟早的事。
2. **只在模拟器测**：真机与低端机的差距（性能、碎片化、传感器）是模拟器给不了的。
3. **忽视弱网与离线**：地铁里刷不出的 App 没有商业价值，弱网策略是必修课。
4. **图片加载随手写**：大图 OOM 与列表卡顿的第一嫌疑人，必须按尺寸与采样率处理。
5. **权限与合规后补**：隐私合规（权限最小化、告知）是上架前置条件，不是收尾工作。
