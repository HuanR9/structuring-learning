# 移动研发细分模块

> 领域模块六节 Schema：领域画像 / 细分路由 / 预设知识骨架 / 权威信源清单 / 进阶检查点 / 常见误区。

## ① 领域画像

移动研发负责 iOS / Android / 跨平台客户端的开发：界面、数据、性能、发布。核心价值是**"在受限设备上交付流畅体验"**——内存、电量、弱网、碎片化是移动端的四大现实约束。

## ② 细分路由

本模块即最小细分单位，不再下分。平台选择（原生 vs 跨平台）作为 L1 的决策变量处理。

## ③ 预设知识骨架

建模（P2）以此树为起点，按用户目标层级裁剪（规则见 `references/core/modeling.md`）。每个叶子节点括注掌握证据。

```
移动研发
├── L1 语言与平台基础
│   ├── 平台选型（原生 iOS/Android vs Flutter/RN：按团队与场景决策；能按团队技能、性能、原生能力和维护成本比较原生与跨平台方案，提交决策矩阵和小型验证任务）
│   ├── 开发语言（Swift / Kotlin / Dart 选一，能写惯用法代码）
│   └── 平台规范（HIG / Material Design：导航、手势、返回逻辑；能依据目标平台当前官方规范实现一条导航/返回流程，并在目标设备验证手势、状态栏和无障碍行为）【时效敏感】
├── L2 UI 层
│   ├── 页面布局与组件（约束/声明式 UI，能还原设计稿）
│   ├── 列表与图片（复用机制、大图加载；能在样例页面实现列表复用和按需图片加载，并用设备观测定位卡顿或内存风险）

│   ├── 网络层（HTTP 封装、长连接、弱网策略与重试；能用弱网和超时场景验证请求取消、重试、幂等与长连接恢复，提交状态时序记录）

├── L4 发布与质量
│   ├── 打包与签名（证书/描述文件/应用市场审核要求；能在测试账户生成可安装的调试/发布包，核对签名身份并整理可复现的构建步骤）

│   └── 灰度与热修复（合规边界内的更新策略；能对照目标平台当前政策与发布机制比较更新路径，写出灰度、回滚和不可用能力边界）【时效敏感】
└── L5 专项层（可选分支）
    ├── 推送与隐私合规（权限申请、隐私清单；能画出权限请求时机和拒绝路径，逐项说明数据用途、最小必要性及适用地区的核对依据）
    ├── 跨平台框架深入（Flutter/RN 的渲染机制与边界；能用 profiler 跟踪一次跨平台界面更新，画出渲染路径并说明原生桥接或重绘的性能边界）
    └── 音视频与地图等 SDK 集成（能在测试应用集成一个 SDK，验证权限拒绝、网络失败、生命周期切换和资源释放）
```

## ⑤ 进阶检查点

| 阶段 | 能力证据（能做成这些即过关） |
|---|---|
| 初级（L1–L2） | 完成一个含网络请求与长列表的页面并在真机流畅运行；讲清一次页面从创建到销毁的生命周期 |
| 中级（L3–L4） | 独立负责一个模块（本地存储+缓存+弱网策略）；用工具定位一次内存泄漏或启动耗时问题 |
| 高级（L5） | 设计客户端的整体架构（分层、模块化）；主导一次崩溃治理或性能专项 |

## ⑥ 常见误区

1. **生命周期不清**：页面/组件生命周期没搞懂，泄漏与空指针是迟早的事。
2. **只在模拟器测**：真机与低端机的差距（性能、碎片化、传感器）是模拟器给不了的。
3. **忽视弱网与离线**：地铁里刷不出的 App 没有商业价值，弱网策略是必修课。
4. **忽视图片资源成本**：大图可能造成内存压力与列表卡顿，应按设备、图片尺寸、缓存策略和实测性能选择缩放与加载方案。
5. **权限与合规后补**：隐私合规（权限最小化、告知）是上架前置条件，不是收尾工作。
