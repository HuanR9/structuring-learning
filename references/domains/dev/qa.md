# 测试工程细分模块

> 领域模块六节 Schema：领域画像 / 细分路由 / 预设知识骨架 / 权威信源清单 / 进阶检查点 / 常见误区。

## ① 领域画像

测试工程负责质量保障的体系化与自动化：测试策略、用例设计、自动化框架、性能验证。核心价值是**"用可复用的工程手段，让质量风险在上线前暴露"**——测试的价值不在发现缺陷的数量，而在对发布决策的支撑。

## ② 细分路由

本模块即最小细分单位，不再下分。

## ③ 预设知识骨架

建模（P2）以此树为起点，按用户目标层级裁剪（规则见 `references/core/modeling.md`）。每个叶子节点括注掌握证据。

```
测试工程
├── L1 测试基础
│   ├── 测试分类（单元/集成/接口/UI/性能/安全的职责边界）
│   ├── 用例设计方法（等价类/边界值/场景法/判定表，能设计覆盖完整分支的用例）
│   └── 缺陷生命周期（严重级别定义、提交一份可复现的高质量缺陷）
├── L2 接口自动化
│   ├── 接口测试框架（Requests/pytest/Allure 类栈，能独立搭框架）
│   ├── 数据准备与清理（Fixture 管理、造数与清数策略）
│   └── 断言设计与结果分析（分层断言、失败可定位性）
├── L3 UI 与 E2E
│   ├── UI 自动化（Web：Selenium/Playwright 的等待与稳定性）
│   ├── 移动端自动化（Appium/UiAutomator 认知）
│   └── 稳定性与 flaky 治理（重试机制、失败根因分类）
├── L4 性能测试
│   ├── 压测工具（JMeter/k6/Locust：场景编排）
│   ├── 指标解读（QPS/RT/百分位/错误率、拐点分析）
│   └── 瓶颈定位配合（与开发协作定位的手段）
└── L5 效能与体系
    ├── CI 中的测试（门禁设计、测试左移）
    ├── 测试平台建设（任务调度、报告聚合、用例管理）
    └── 质量度量（覆盖率/逃逸率/线上缺陷分布，用数据说质量）
```

## ⑤ 进阶检查点

| 阶段 | 能力证据（能做成这些即过关） |
|---|---|
| 初级（L1–L2） | 为一个接口设计完整用例（含异常与边界）并自动化；提交的缺陷 100% 可复现且定位清晰 |
| 中级（L3–L4） | 搭建一套可维护的接口自动化框架（数据隔离+报告+CI 集成）；独立完成一次压测并输出含瓶颈分析的 report |
| 高级（L5） | 设计质量门禁与度量体系；主导测试平台建设或专项质量改进 |

## ⑥ 常见误区

1. **只点页面不设计用例**：手工探索是必要的，但无方法论的"点点点"发现不了系统性风险。
2. **自动化堆数量无维护**：用例跑不动、flaky 满天飞时，自动化资产就变成了负债。
3. **覆盖率迷信**：100% 行覆盖 ≠ 高质量，断言设计比覆盖率数字重要。
4. **忽视测试左移**：缺陷发现越晚修复成本越高，评审阶段介入比上线后救火划算得多。
5. **性能测试只跑不分析**：没有目标值与瓶颈分析的压测，只是让机器空转。
