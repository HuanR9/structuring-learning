# 架构设计细分模块

> 领域模块六节 Schema：领域画像 / 细分路由 / 预设知识骨架 / 权威信源清单 / 进阶检查点 / 常见误区。

## ① 领域画像

架构设计负责系统级的技术决策：结构选型、数据流转、演进路径与风险权衡。核心价值是**"在约束条件下做出当下最优决策，并为未来留出演进空间"**——架构的本质是权衡，不是名词的堆砌。

## ② 细分路由

本模块即最小细分单位，不再下分。

## ③ 预设知识骨架

建模（P2）以此树为起点，按用户目标层级裁剪（规则见 `references/core/modeling.md`）。每个叶子节点括注掌握证据。

```
架构设计
├── L1 设计基础
│   ├── 架构风格（分层/微服务/事件驱动/Serverless 的适用与代价；能针对同一业务约束比较两种架构风格，提交决策记录，列出关键质量属性、复杂度和失效代价）
│   ├── 设计原则（SOLID、高内聚低耦合，能指出现有代码的违反点）
│   └── 架构表达（C4 模型/ADR，能把系统讲清楚给不同角色听）
├── L2 数据架构
│   ├── 存储选型（关系/NoSQL/缓存/搜索/对象存储的决策矩阵；能按读写模式、一致性和数据规模为案例做存储选型，交付决策矩阵及迁移成本说明）
│   ├── 数据一致性（分布式事务、最终一致、幂等的设计取舍；能针对一次重复投递或部分失败场景选择一致性策略，写明恢复路径与用户可见影响）
│   └── 数据流转（CDC、数仓分层认知、实时/离线链路；能画出一条 CDC 到实时/离线消费的数据链路，标注重复、延迟、回放和数据质量控制点）
├── L3 分布式架构
│   ├── 服务拆分与治理（拆分依据、注册发现、配置中心；能为案例划分服务边界与数据所有权，交付依赖图和拆分/回滚步骤）
│   ├── 高可用模式（熔断/限流/重试/隔离的组合与边界；能用故障场景表说明限流、熔断、重试和隔离的组合顺序及级联风险）
│   └── 分布式组件（分布式锁、MQ、任务调度的选型；能按一致性、可用性和运维约束比较锁、队列或调度方案，列出故障语义和取舍）
├── L4 非功能设计
│   ├── 性能（容量模型、水平/垂直扩展路径；能根据样例负载估算资源需求与瓶颈，并比较扩展方案的成本和限制）
│   ├── 安全（认证鉴权体系、数据安全分级防护；能为样例系统画出信任边界和威胁清单，并把认证、授权与数据分级措施对应到风险）
│   └── 可观测性设计（日志/指标/链路的一体化设计；能为一条关键业务链路定义日志、指标和 Trace 的关联字段，并说明隐私与采样边界）
└── L5 演进与治理
    ├── 架构决策记录（ADR 的写法与使用；能写一份包含背景、备选项、决策、后果和复审触发条件的 ADR）
    ├── 遗留系统演进（绞杀者模式、防腐层、渐进式迁移；能为遗留模块制定分阶段迁移计划，列出双写/切换验证、回滚条件和防腐层边界）
    └── 技术选型方法论（PoC、社区健康度、TCO 评估；能用 PoC 验收项、维护活跃度和 TCO 估算比较候选技术，并记录不确定假设）
```

## ⑤ 进阶检查点

| 阶段 | 能力证据（能做成这些即过关） |
|---|---|
| 初级（L1） | 读懂现有系统的架构图并讲清各模块职责与依赖；用 C4 图重绘一个系统 |
| 中级（L2–L4） | 独立设计一个中型系统（含存储选型、高可用与容量评估）并写出 ADR；主导一次服务拆分落地 |
| 高级（L5） | 主导遗留系统的渐进式演进；完成一次重大技术选型（PoC+TCO 分析+决策记录） |

## ⑥ 常见误区

1. **追新堆名词**：技术选型看谁火而不是看谁合适，微服务/中台/Sidecar 上了再说。
2. **忽视非功能需求**：只画功能模块图，性能、安全、可观测性上线前才想。
3. **设计过度**：为想象中的亿级流量设计，团队三个人维护，复杂度先压垮自己。
4. **只画图不讲权衡**：架构文档没有备选方案与取舍分析，等于没有思考过程。
5. **脱离团队与历史**：不考虑团队技术栈、历史包袱与运维能力，"最优雅"的方案落不了地。
