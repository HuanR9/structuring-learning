# AI 应用工程细分模块

> 领域模块六节 Schema：领域画像 / 细分路由 / 预设知识骨架 / 权威信源清单 / 进阶检查点 / 常见误区。

## ① 领域画像

AI 应用工程关注将现成模型能力集成进软件并可靠交付，核心是让模型在明确边界内完成任务，并通过检索、工具、评估、安全控制和可观测性达到可维护的质量。默认聚焦大语言模型应用，不默认要求训练基础模型。

## ② 细分路由

本模块是现阶段 AI 应用工程的入口。目标若主要是模型训练、数学推导或数据科学，按目标改走通用流程；若主要是产品定位和商业验证，关联产品类，不把本模块扩成 AI 全景课。

## ③ 预设知识骨架

建模（P2）以此树为起点，按用户目标层级裁剪（规则见 `references/core/modeling.md`）。每个叶子节点括注掌握证据。

```
AI 应用工程
├── L1 基础与边界
│   ├── 模型能力与限制（生成、上下文窗口、随机性、幻觉；能用代表性样例区分模型适用任务、失败模式与需外部验证的输出）
│   ├── API 与结构化输出（消息、JSON Schema、流式响应、错误处理；能构建调用样例并验证超时、限流、无效输出和重试边界）
│   └── 任务拆解与提示设计（指令、上下文、示例、约束；能为一个任务编写可复用提示并用一组固定样例比较版本差异）
├── L2 应用模式
│   ├── 检索增强生成（切分、嵌入、检索、重排、引用；能搭建小型 RAG 流程，用问题集检查召回、引用正确性和拒答边界）
│   ├── 工具调用与工作流（函数调用、校验、状态、失败恢复；能实现一个受限工具流程并验证无效参数、工具失败和重复调用）
│   └── 对话状态与上下文管理（历史、摘要、权限隔离、上下文预算；能设计多轮状态策略并用跨用户/跨会话样例验证隔离）
├── L3 质量与安全
│   ├── 应用评估（代表性数据集、离线评估、人工评审、回归；能建立覆盖成功与失败场景的评估集并比较两版结果）
│   ├── 安全与滥用防护（提示注入、越权工具、敏感信息、输出校验；能针对一个 RAG 或工具应用列出威胁并验证至少一项纵深防护）
│   └── 人类监督与失败兜底（拒答、审批、升级、回退到确定性流程；能为高影响输出设计人工审核点并演练异常路径）
└── L4 生产交付
    ├── 部署与可靠性（供应商抽象、超时、退避、限流、降级；能为一个应用定义服务目标并演练供应商不可用时的降级路径）
    ├── 可观测性与隐私（请求追踪、质量/延迟/成本指标、日志脱敏；能定位一条失败调用并验证日志不泄露不必要的敏感数据）
    └── 成本与模型选择（质量、延迟、价格、上下文与任务约束；能用固定评估集比较候选模型并说明选型依据和成本假设）
```

## ④ 权威信源清单

| 级别 | 信源 | 备注 |
|---|---|---|
| 官方 | 所选模型供应商的 API、结构化输出、工具调用、检索、评估与安全文档 | 按实际供应商和模型版本查阅，能力及接口变化较快 |
| 官方 | [OpenAI Agents 指南](https://developers.openai.com/api/docs/guides/agents)、[Agent Evals](https://developers.openai.com/api/docs/guides/agent-evals)、[Tracing](https://developers.openai.com/api/docs/guides/agents-api/tracing) | 示例之一；概念可迁移，API 细节不可假定跨供应商一致 |
| 官方 | Anthropic、Google 等所用模型平台文档 | 按项目实际技术栈选择，不要求学习所有平台 |
| 标准/社区 | [OWASP Top 10 for LLM Applications](https://genai.owasp.org/llm-top-10/) | 当前页面列出 2025 风险清单；学习时核对版本 |
| 标准/社区 | [NIST AI Risk Management Framework](https://www.nist.gov/itl/ai-risk-management-framework) | 风险治理参考；不替代应用层威胁建模和工程测试 |

## ⑤ 进阶检查点

| 阶段 | 能力证据（能做成这些即过关） |
|---|---|
| 初级（L1） | 实现一次模型 API 调用，处理结构化输出与失败场景，并用固定样例检查提示版本 |
| 中级（L2–L3） | 构建带检索或受限工具的应用；提交评估集、结果对比、威胁清单和失败兜底设计 |
| 高级（L4） | 为目标用户和负载设计可观测、可降级、成本可估算的上线方案，并演练供应商异常与安全事件 |

## ⑥ 常见误区

1. **把提示词当全部工程**：数据质量、检索、工具权限、评估和故障处理同样决定应用质量。
2. **只用演示样例验收**：固定少量成功样例无法代表真实分布，应覆盖边界、失败和滥用场景。
3. **让模型输出直接触发高影响操作**：对外发送、付款、删除或权限变更等动作应使用确定性校验和适当的人类审批。
4. **把 RAG 当作事实保证**：检索结果可能缺失、过时或被恶意内容污染，必须验证引用和拒答行为。
5. **混淆模型能力与产品价值**：技术可行不代表用户问题值得解决；产品定位与商业验证归产品领域协作处理。
