# 前端研发细分模块

> 领域模块六节 Schema：领域画像 / 细分路由 / 预设知识骨架 / 权威信源清单 / 进阶检查点 / 常见误区。

## ① 领域画像

前端研发负责界面与交互的工程实现：把设计稿变成可运行、可维护、性能达标的 Web 界面。核心价值是**"还原设计意图，且在任何设备上都快而稳"**——框架会过时，HTML/CSS/JS 基础与工程思维不过时。

## ② 细分路由

本模块即最小细分单位，不再下分。小程序 / Node 中间层作为可选分支（L5）。

## ③ 预设知识骨架

建模（P2）以此树为起点，按用户目标层级裁剪（规则见 `references/core/modeling.md`）。每个叶子节点括注掌握证据。

```
前端研发
├── L1 基础层
│   ├── HTML/CSS 精讲（盒模型/选择器优先级/弹性布局/网格，能不看文档还原复杂布局）
│   ├── JavaScript 语言核心（原型链/闭包/事件循环/异步，能讲清一次 Promise 链的执行顺序）
│   └── TypeScript（泛型与工具类型，能定义复杂业务模型的类型）
├── L2 框架层
│   ├── 主流框架之一（Vue3 / React：渲染机制与响应式原理；能通过一个小例子解释状态更新如何触发渲染，并定位一次常见更新问题）
│   ├── 组件设计与状态管理（props/emit、组合式 API 或 Hooks 的边界；能为一个交互组件定义输入、事件和状态归属，并说明何时拆分或提升状态）
│   ├── 路由与工程化（Vite/Webpack 构建链路、分包、环境配置；能配置开发/生产环境和路由分包，构建后检查产物、资源路径及环境变量是否符合预期）
│   └── 请求与数据层（拦截器/错误统一处理/缓存策略；能实现请求封装，统一处理超时、取消、鉴权失效和错误提示，并用测试验证边界）
├── L3 质量层
│   ├── 调试与 DevTools（Elements/Network/Performance 面板的排障用法；能用 Network 与 Performance 面板定位给定页面的请求或渲染瓶颈，提交证据截图和修复验证）
│   ├── 单测与 E2E（Vitest/Playwright：组件测试与关键路径覆盖；能为关键组件和一条用户路径编写测试，证明断言覆盖关键状态且等待策略稳定）
│   └── 代码规范（ESLint/Prettier、TypeScript strict 的渐进落地；能逐步启用 lint、格式化与 TypeScript strict，在样例改动中清理错误并记录合理例外）
├── L4 性能与体验层
│   ├── 加载性能（懒加载/路由分包/CDN/资源体积预算；能用性能面板定位一个加载瓶颈，选择优化手段并比较优化前后的关键指标）
│   ├── 渲染性能（重排重绘、长列表虚拟化、大数据量渲染；能从性能记录定位长任务或重复渲染，提出修复并验证交互与性能结果）
│   └── 兼容与适配（移动端适配、多浏览器差异清单；能建立目标浏览器/设备矩阵，复现并修复一项差异，保留修复前后验证记录）
└── L5 工程体系层（可选分支）
    ├── 组件库与设计系统落地（Token 到组件的映射；能把一组设计 Token 接入组件样式，并用主题切换或视觉回归检查映射结果）
    ├── 微前端认知（模块联邦的适用与代价；能用模块联邦或替代方案画出运行时依赖图，提交适用性决策及版本/部署失败边界）
    └── Node.js 中间层（BFF/SSR 的边界；能针对一个业务接口划定 BFF 与 SSR 职责，交付请求流程图和可运行的最小接口样例）
```

## ⑤ 进阶检查点

| 阶段 | 能力证据（能做成这些即过关） |
|---|---|
| 初级（L1–L2） | 不看设计稿注释还原一个复杂页面；独立完成一个含路由/状态/接口的 SPA 并部署 |
| 中级（L3–L4） | 用 Performance 面板定位并修复一次渲染卡顿；为一个项目补齐关键路径 E2E 测试；把首屏加载时间压掉一半并说出每项优化的依据 |
| 高级（L5） | 搭建可复用的组件库并落地到多个项目；设计一套微前端拆分方案并说明代价 |

## ⑥ 常见误区

1. **会框架 API 不懂语言原理**：面试造火箭工作拧螺丝不可怕，可怕的是框架一换就归零。
2. **忽视可访问性与语义化**：div 一把梭、无 alt 无键盘焦点，短期无感，合规与体验双输。
3. **只测 Chrome 不测兼容**：不列浏览器支持矩阵，低端机与旧版本浏览器必出妖蛾子。
4. **性能凭感觉**：不看 Core Web Vitals（LCP/FID/CLS）的优化都是玄学。
5. **CSS 越写越乱**：不用方法论（BEM/原子类/组件作用域）约束，千人千面的样式互相覆盖。
