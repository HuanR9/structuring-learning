# 后端研发细分模块

> 领域模块六节 Schema：领域画像 / 细分路由 / 预设知识骨架 / 权威信源清单 / 进阶检查点 / 常见误区。

## ① 领域画像

后端研发负责服务端的功能正确、性能达标与稳定运行：业务逻辑、数据存储、接口设计、并发处理、线上排障。核心价值是**"接口对、扛得住、查得清"**。学习需先选一门主力语言（Java / Go / Python 选一深耕），其余触类旁通。

## ② 细分路由

本模块即最小细分单位，不再下分。语言选择作为 L1 的内部变量处理（骨架中标注，按用户选定语言替换信源）。

## ③ 预设知识骨架

建模（P2）以此树为起点，按用户目标层级裁剪（规则见 `references/core/modeling.md`）。每个叶子节点括注掌握证据。

```
后端研发
├── L1 语言与计算机基础
│   ├── 主力语言精通（语法/集合/并发库/生态工具链，能独立写完一个 CLI 工具）
│   ├── 数据结构与算法（数组/链表/哈希/树/排序，能手写常用结构与复杂度分析）
│   ├── 操作系统基础（进程线程、内存、IO 模型——能解释阻塞/非阻塞与多路复用）
│   └── 计算机网络（TCP 三次握手与状态机、HTTP/HTTPS 协议细节；能画出一次 TCP 建连和 HTTP 请求的时序图，并根据抓包或日志解释关键状态变化）
├── L2 开发能力层
│   ├── Web 框架与工程化（Spring Boot / Gin / FastAPI 之一，能搭规范的分层工程）
│   ├── 数据库与 SQL（索引、事务、关联查询，能用执行计划排查慢 SQL）
│   ├── 缓存（Redis 数据结构选型、缓存穿透/击穿/雪崩的应对；能为一个接口设计缓存键、失效和击穿保护策略，并用测试覆盖过期、并发与异常路径）
│   ├── 消息队列（Kafka/RocketMQ 语义：至少一次/顺序/堆积处理；能搭建小型生产消费样例，验证投递语义、幂等/顺序处理及积压告警）
│   └── API 设计（REST 规范、认证鉴权 JWT/Session、幂等与防重；能为一个业务接口写出请求/响应、错误语义、鉴权和重试规则，并覆盖重复请求场景）
├── L3 质量层
│   ├── 测试（单元测试/集成测试/接口测试，覆盖率的合理预期；能为一个服务接口编写单元与集成测试，说明覆盖了哪些风险及为何不追求某个覆盖率数字）
│   ├── 日志与调试（日志级别规范、基于日志与链路的排障流程；能用带关联 ID 的日志和调用链还原一次故障时间线，并提交根因与复现步骤）
│   └── 代码质量（设计模式常用模式、重构手法、Code Review 要点；能针对一段有异味的服务代码提出小步重构方案，配测试说明行为保持不变）
├── L4 并发与性能层
│   ├── 并发编程（锁/线程池/异步编排，能分析并修复一个并发 bug）
│   ├── 运行时调优（JVM GC / Go pprof / Python GIL 认知，按选定语言取对应分支；能用所选语言的 profiler 检查一个性能问题，提交前后指标和可复现的调优结论）
│   └── 性能压测（压测工具、QPS/RT/百分位指标解读、瓶颈定位方法论；能定义压测负载、环境和停止条件，并从结果中提出可验证的瓶颈假设）
├── L5 分布式与架构层
│   ├── 分布式基础（CAP、BASE、分布式锁与一致性协议的认知边界；能针对案例画出一致性/可用性取舍和锁失效时序，并说明方案成立的前提）
│   ├── 微服务治理（注册发现、配置中心、服务间调用与超时重试；能为服务调用配置超时、重试和熔断策略，用故障注入验证重试风暴与降级边界）
│   ├── 高可用设计（限流/熔断/降级/隔离，能给出组合方案与代价）
│   └── 系统设计方法论（短链/秒杀/Feed 等经典场景的设计推演；能针对一个场景画出主要组件和请求路径，估算关键容量并说明至少一项失效取舍）
└── L6 工程效能（可选分支，按需选修）
    ├── CI/CD（流水线搭建与制品管理；能为一个服务配置构建、测试和制品发布流水线，并验证失败时的阻断与重跑行为）
    ├── 容器与 K8s 基础（镜像、部署、服务暴露；能把一个最小服务构建为镜像并部署到隔离集群，验证健康检查、服务访问和回滚）
    └── 可观测性（Metrics/Logging/Tracing 三件套落地；能为一个请求贯通指标、结构化日志与 trace，提交查询/告警样例并定位一次模拟故障）
```

| 级别 | 信源 | 备注 |
|---|---|---|

## ⑤ 进阶检查点

| 阶段 | 能力证据（能做成这些即过关） |
|---|---|
| 初级（L1–L2） | 独立完成一个含数据库+缓存+鉴权的 CRUD 服务并部署；解释一次慢查询的优化过程 |
| 中级（L3–L4） | 为一个模块补齐单元测试并说出取舍；用压测+ profiling 定位并修复一个性能瓶颈；讲清一次线上问题的完整排障过程 |
| 高级（L5） | 独立设计一个高并发场景（如秒杀）的完整方案并写出权衡分析；主导一次服务拆分或稳定性改造 |

## ⑥ 常见误区

1. **语言松鼠病**：同时学多门语言导致无一精通，先一门到"能用"再扩展。
2. **只刷框架不学基础**：框架三年一换，操作系统/网络/数据结构十年不变，L1 不牢地动山摇。
3. **只看教程不写项目**：后端能力以可运行代码为检验标准，看十遍不如写一遍。
4. **忽视线上视角**：本地能跑 ≠ 线上可用，尽早接触日志、监控、排障（L3/L4 不是高级专属）。
5. **架构过早**：没经历过单机瓶颈就学微服务，容易只会名词不会取舍，L5 建立在 L2–L4 的实战痛感上。
