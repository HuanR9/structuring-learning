# 研发类领域模块（dev）

## 领域画像

研发类关注用代码把需求变成可靠运行的软件：从一门语言到工程化，从单机到分布式。学习主线通常是"懂语言 → 懂工程 → 懂性能 → 懂架构"。

## 细分路由（L2）

| 触发词 | 细分 | 模块文件 | 状态 |
|---|---|---|---|
| 后端、服务端、Java、Go、Python 后端、接口、微服务 | 后端研发 | `backend.md` | ✅ 二期 |
| 前端、Vue、React、TypeScript、页面 | 前端研发 | `frontend.md` | ✅ 二期 |
| 客户端、iOS、Android、Flutter、小程序 | 移动研发 | `mobile.md` | ✅ 二期 |
| 测试、QA、自动化测试、性能测试 | 测试工程 | `qa.md` | ✅ 二期 |
| 架构、架构师、系统设计 | 架构设计 | `architecture.md` | ✅ 二期 |

- 命中 🔜 细分：按 `references/core/workflow.md` 通用流程建模，并提示用户可沉淀为该细分模块。
- 用户目标跨多个细分（如"学编程"无细分）：先用本文件给出细分全景，引导用户选一个主攻方向（通常建议先定语言与岗位方向），不要全铺。

## 通用信源（研发类共享）

- 官方文档优先：语言与框架的官方文档（版本以生产在用为准）。
- 经典书籍：按细分模块清单取用。
- 实践原则：证据形式应匹配细分主题。语言、框架和工程化主题优先用可运行代码验证；测试工程可交付测试计划、自动化用例和结果；架构设计可交付图、ADR、PoC 或故障推演，不要求每个模块都做独立项目。
- 边界提示：后端模块聚焦服务实现与运行；架构模块聚焦跨组件决策、质量属性和演进方案。涉及服务设计时可关联，但不要重复讲解同一套实现细节。
- 边界提示：后端模块中的 CI/CD 关注应用代码的构建、测试与制品；云原生模块关注容器化、集群发布和 GitOps。测试工程定义质量策略与自动化验证，研发模块中的测试只保留与自身交付环节直接相关的部分。
