# 运维类领域模块（ops）

## 领域画像

运维类关注系统的稳定运行、交付与治理：从单机到集群，从手工到自动化。学习主线通常是"懂系统 → 懂服务 → 懂架构 → 懂稳定性工程"。

## 细分路由（L2）

| 触发词 | 细分 | 模块文件 | 状态 |
|---|---|---|---|
| DBA、数据库、MySQL、PostgreSQL、Redis、SQL、慢查询、备份恢复 | DBA（数据库运维） | `dba.md` | ✅ 首期 |
| SRE、稳定性、监控、告警、故障应急、oncall | SRE（稳定性工程） | `sre.md` | ✅ 二期 |
| Linux、系统、性能调优、内核、shell | 系统运维 | `system.md` | ✅ 二期 |
| 网络、TCP、DNS、负载均衡、抓包 | 网络运维 | `network.md` | ✅ 二期 |
| K8s、容器、Docker、云原生、GitOps、集群发布、CI/CD | 容器与云原生 | `cloud-native.md` | ✅ 二期 |

- 命中 🔜 细分：按 `references/core/workflow.md` 通用流程建模，并提示用户可沉淀为该细分模块。
- 用户目标跨多个细分（如"学运维"无细分）：先用本文件给出细分全景，引导用户选一个主攻方向，不要全铺。
- 边界提示：DBA 聚焦数据库引擎、数据保护与数据库服务运维；系统运维聚焦主机与操作系统；网络运维聚焦连通与传输链路；云原生聚焦容器/Kubernetes 的交付和运行机制；SRE 横跨这些组件，聚焦可靠性目标、应急和风险治理。按用户要解决的主要问题选主模块，确有依赖时再关联其他模块。
- CI/CD 路由：应用代码的构建、测试和制品发布归研发类；容器平台部署、集群发布和 GitOps 归云原生。仅说“CI/CD”时，先确认用户要解决哪一段交付链路。

## 通用信源（运维类共享）

- 官方文档优先：各组件官网文档（版本以生产在用版本为准）。
- 经典书籍：按细分模块清单取用。
- 实践原则：运维类学习优先在本地容器、虚拟机或专用测试环境验证；生产环境不得作为练习场。对高成本、危险或无法本地复现的主题，可用桌面推演、配置审查或故障注入记录作为证据，不强求执行真实变更。
