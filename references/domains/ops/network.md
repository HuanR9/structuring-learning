# 网络运维细分模块

> 领域模块六节 Schema：领域画像 / 细分路由 / 预设知识骨架 / 权威信源清单 / 进阶检查点 / 常见误区。

## ① 领域画像

网络运维保障连通性、性能与安全：协议理解、架构配置、故障定位。核心价值是**"分层定位问题"**——网络问题跨越物理到应用多层，能用分层法把大象装进冰箱，比背配置命令更重要。

## ② 细分路由

本模块即最小细分单位，不再下分。

## ③ 预设知识骨架

建模（P2）以此树为起点，按用户目标层级裁剪（规则见 `references/core/modeling.md`）。每个叶子节点括注掌握证据。

```
网络运维
├── L1 协议基础
│   ├── TCP/IP 分层模型（每层职责与对应故障现象，能画协议栈图）
│   ├── 交换与路由（VLAN/Trunk、静态路由、OSPF 基础；能在隔离拓扑配置 VLAN 和路由，提交端到端连通测试及路由表证据）
│   ├── DNS 体系（解析流程、记录类型、排查手段；能用 dig 或等效工具检查一条解析链路，定位样例中的记录或缓存问题并解释证据）
│   └── HTTP/HTTPS 与 TLS（握手流程、证书链、常见错误码；能用客户端工具检查一次 TLS 握手和证书链，定位一个证书/协议错误并记录验证命令）
├── L2 网络服务
│   ├── DHCP 与 NTP（地址分配、时间同步的运维意义；能在实验网段检查 DHCP 租约和 NTP 同步状态，说明失效症状及时间偏差影响）
│   ├── VPN（IPSec/SSL VPN 的选型与边界；能按访问对象和信任边界比较 VPN 方案，画出隧道与路由范围并列出密钥/客户端风险）
│   └── 负载均衡（LVS/HAProxy/NGINX：四层/七层差异与选型；能搭建一个测试后端比较四层/七层转发，验证健康检查、会话保持和节点故障切换）
├── L3 排障层
│   ├── 分层排障法（物理→链路→网络→传输→应用的检查清单；能针对一例不可达故障按物理到应用层逐步检查，提交每层证据和定位依据）
│   ├── 抓包分析（tcpdump 过滤表达式、Wireshark 流分析；能写出针对目标流量的 tcpdump 过滤式，从抓包重建连接时序并解释丢包/重传证据）
│   └── 常见故障模式（丢包/延迟/MTU/DNS 劫持/路由环路的特征；能从样例数据区分丢包、延迟、MTU、DNS 和路由问题，给出下一条验证命令及其判别结果）
├── L4 云网络
│   ├── VPC 与子网（网段规划、路由表；能为给定网段和环境设计 CIDR、路由表与地址预留，验证无重叠且保留扩展空间）
│   ├── 安全组与 ACL（有状态/无状态差异；能为业务流量写出有状态规则矩阵，通过正反向连通测试证明最小开放范围）
│   └── 专线与对等连接（混合云连通方案；能为混合云案例画出路由和冗余拓扑，比较故障切换、地址冲突与运维责任边界）
└── L5 安全层
    ├── 防火墙策略设计（最小化原则、策略梳理；能为样例服务整理来源、目标、端口、理由和失效日期，并验证允许与拒绝路径）
    └── DDoS 与 Web 攻击防护认知（能针对模拟威胁绘制分层防护和应急升级路径，并以当前官方资料核对能力边界）【时效敏感】
```

## ⑤ 进阶检查点

| 阶段 | 能力证据（能做成这些即过关） |
|---|---|
| 初级（L1–L3） | 读懂一次 HTTPS 抓包并讲清握手过程；独立配置 VLAN + 静态路由连通两个网段 |
| 中级（L2–L3） | 用分层法定位一次真实网络故障并给出证据（ping/traceroute/抓包）；设计一套负载均衡架构 |
| 高级（L4–L5） | 设计混合云网络架构（含安全策略）；完成一次防火墙策略梳理与收敛 |

## ⑥ 常见误区

1. **只会 ping/curl 不懂分层**：不通就重启，问题复发了也不知道为什么，分层检查清单才是排障骨架。
2. **忽视 DNS 与 TLS**：大量"网络问题"最后定位到 DNS 缓存或证书链，这两层是最容易被跳过的。
3. **防火墙全通图省事**：策略只加不减，规则几千条谁也看不懂，等于没有防护。
4. **照搬物理网络经验上云**：安全组有状态、路由表驱动、无广播域，物理网络直觉在云上经常失效。
5. **不抓包靠猜**：应用层"偶发超时"的真相都在包里，养成抓包习惯能少走 80% 弯路。
