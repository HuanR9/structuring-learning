# 系统运维细分模块

> 领域模块六节 Schema：领域画像 / 细分路由 / 预设知识骨架 / 权威信源清单 / 进阶检查点 / 常见误区。

## ① 领域画像

系统运维负责单机到集群的系统管理：安装部署、配置管理、性能分析、批量自动化与安全加固。核心价值是**"机器可控、性能可见、批量可复制"**——规模化的前提是每台机器的行为可预期。

## ② 细分路由

本模块即最小细分单位，不再下分。

## ③ 预设知识骨架

建模（P2）以此树为起点，按用户目标层级裁剪（规则见 `references/core/modeling.md`）。每个叶子节点括注掌握证据。

```
系统运维
├── L1 系统基础
│   ├── Linux 安装与目录体系（FHS 标准，能说清每个核心目录的用途）
│   ├── 命令行与 shell 脚本（文本处理三件套，能写可维护的巡检脚本）
│   ├── 用户权限与文件系统（rwx/ACL/SELinux 基础）
│   └── 进程与服务管理（systemd 单元文件，能写一个自定义服务）
├── L2 网络与存储
│   ├── 网络配置（IP/路由/DNS/firewalld，能独立配置一台多网卡服务器）
│   ├── 磁盘与文件系统（LVM/RAID/NFS，能完成一次在线扩容）
│   └── 内核参数调优（常见参数含义与风险边界）
├── L3 性能分析
│   ├── 四维分析法（CPU/内存/IO/网络各自的关键指标）
│   ├── 工具链（top/vmstat/iostat/sar/ss/strace，能选对工具）
│   └── 内核可观测（/proc 与 sysfs 关键文件、eBPF 入门）
├── L4 批量与自动化
│   ├── 配置管理（Ansible：playbook/role/幂等性）
│   ├── 批量执行与巡检（并行 SSH、巡检报告生成）
│   └── 资产与基线管理（CMDB 认知、配置基线核查）
└── L5 安全加固
    ├── 系统加固（SSH 加固、防火墙策略、最小化服务）
    ├── 账号与审计（sudo 分级、auditd、登录审计）
    └── 合规基线（等保要求映射）【时效敏感】
```

## ⑤ 进阶检查点

| 阶段 | 能力证据（能做成这些即过关） |
|---|---|
| 初级（L1–L2） | 独立完成装机→网络→存储配置→写巡检脚本全流程；解释 sar 输出中的一处性能异常 |
| 中级（L3–L4） | 用工具链定位一次真实性能瓶颈并给出证据链；用 Ansible 管理 50 台机器的配置与巡检 |
| 高级（L5） | 设计一套批量自动化体系或内核/系统级调优方案并说明风险边界；完成一次安全加固与基线核查 |

## ⑥ 常见误区

1. **只会命令不懂原理**：命令参数背得熟，不理解系统机制，遇到非常规问题就无从下手。
2. **忽视备份与安全**：系统运维的第一职责是数据安全，加固与备份不是"有空再做"。
3. **只会单机不会批量**：管理 3 台靠手速，管理 300 台必须靠自动化，手动操作是规模化第一大敌。
4. **盲目调参**：不看指标凭经验改内核参数，制造的问题比解决的问题多。
5. **版本混用无基线**：多台机器配置漂移无察觉，基线核查与配置管理才能保证可预期。
