# 系统运维细分模块

> 领域模块六节 Schema：领域画像 / 细分路由 / 预设知识骨架 / 权威信源清单 / 进阶检查点 / 常见误区。

## ① 领域画像

系统运维负责单机到集群的系统管理：安装部署、配置管理、性能分析、批量自动化与安全加固。核心价值是**"机器可控、性能可见、批量可复制"**——规模化的前提是每台机器的行为可预期。

## ② 细分路由

本模块即最小细分单位，不再下分。

## ③ 预设知识骨架

建模（P2）以此树为起点，按用户目标层级裁剪（规则见 `references/core/modeling.md`）。每个叶子节点括注掌握证据。

```
系统运维
├── L1 系统基础
│   ├── Linux 安装与目录体系（FHS 标准，能说清每个核心目录的用途）
│   ├── 命令行与 shell 脚本（文本处理三件套，能写可维护的巡检脚本）
│   ├── 用户权限与文件系统（rwx/ACL/SELinux 基础；能为样例服务配置最小权限与 ACL，使用正反向访问测试证明权限边界）
│   └── 进程与服务管理（systemd 单元文件，能写一个自定义服务）
├── L2 网络与存储
│   ├── 网络配置（IP/路由/DNS/firewalld，能独立配置一台多网卡服务器）
│   ├── 磁盘与文件系统（LVM/RAID/NFS，能完成一次在线扩容）
│   └── 内核参数调优（常见参数含义与风险边界；能在可回滚的虚拟机调整一个参数，对比基线指标并记录副作用和恢复步骤）
├── L3 性能分析
│   ├── 四维分析法（CPU/内存/IO/网络各自的关键指标；能用样例 sar/vmstat/iostat/网络数据定位主要资源瓶颈，说明排除其他维度的证据）
│   ├── 工具链（top/vmstat/iostat/sar/ss/strace，能选对工具）
│   └── 内核可观测（/proc 与 sysfs 关键文件、eBPF 入门；能从 /proc 或 sysfs 找到目标指标，运行一次安全的 eBPF 观测并解释输出限制）
├── L4 批量与自动化
│   ├── 配置管理（Ansible：playbook/role/幂等性；能写一个 Ansible role 并连续执行两次，证明幂等性和目标主机范围受控）
│   ├── 批量执行与巡检（并行 SSH、巡检报告生成；能对测试主机集执行并行巡检，输出带失败项、采集时间和主机标识的报告）
│   └── 资产与基线管理（CMDB 认知、配置基线核查；能为样例资产定义必需字段和配置基线，发现一次漂移并留下复核记录）
└── L5 安全加固
    ├── 系统加固（SSH 加固、防火墙策略、最小化服务；能为测试主机制定 SSH、防火墙和服务最小化清单，并逐项验证加固后访问能力）
    ├── 账号与审计（sudo 分级、auditd、登录审计；能配置一条权限分级和审计查询流程，从样例日志还原账号操作并核对留存范围）
    └── 合规基线（等保要求映射；能把一个控制要求映射到主机配置和审计证据，并标注标准版本与待核验条款）【时效敏感】
```

## ⑤ 进阶检查点

| 阶段 | 能力证据（能做成这些即过关） |
|---|---|
| 初级（L1–L2） | 独立完成装机→网络→存储配置→写巡检脚本全流程；解释 sar 输出中的一处性能异常 |
| 中级（L3–L4） | 用工具链定位一次性能瓶颈并给出证据链；用 Ansible 对样例主机清单执行可重复配置与巡检，并验证幂等性和失败处理 |
| 高级（L5） | 设计一套批量自动化体系或内核/系统级调优方案并说明风险边界；完成一次安全加固与基线核查 |

## ⑥ 常见误区

1. **只会命令不懂原理**：命令参数背得熟，不理解系统机制，遇到非常规问题就无从下手。
2. **忽视备份与安全**：系统运维的第一职责是数据安全，加固与备份不是"有空再做"。
3. **只会单机不会批量**：重复操作、配置漂移或变更风险升高时，应逐步用脚本和配置管理提升一致性；是否自动化取决于重复频率、失败代价和维护成本，不设固定机器数量门槛。
4. **盲目调参**：不看指标凭经验改内核参数，制造的问题比解决的问题多。
5. **版本混用无基线**：多台机器配置漂移无察觉，基线核查与配置管理才能保证可预期。
