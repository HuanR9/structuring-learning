# B端产品细分模块

> 领域模块六节 Schema：领域画像 / 细分路由 / 预设知识骨架 / 权威信源清单 / 进阶检查点 / 常见误区。

## ① 领域画像

B端产品面向企业客户：以提效、控风险、支撑业务决策为目标，通过流程线上化与数据沉淀创造价值。核心价值是**"把业务语言翻译成系统语言"**——与 C 端最大的差异是：使用者、购买者、决策者往往不是同一个人。

## ② 细分路由

本模块即最小细分单位，不再下分。

## ③ 预设知识骨架

建模（P2）以此树为起点，按用户目标层级裁剪（规则见 `references/core/modeling.md`）。每个叶子节点括注掌握证据。

```
B端产品
├── L1 认知层
│   ├── B端 vs C端 差异（决策链/使用者角色/价值衡量，能对比表格说清五点差异）
│   ├── 企业组织与流程认知（部门墙、审批链、岗位分工）
│   └── 目标行业知识（监管、术语、核心业务流，能画出行业主链路）
├── L2 需求层
│   ├── 业务调研（流程梳理、干系人访谈，能输出业务现状全景图）
│   ├── 需求抽象（个性化需求 vs 平台化能力的取舍模型）
│   └── 版本与交付节奏（MVP 验证、按业务节点排期）
├── L3 方案层
│   ├── 信息架构（复杂表单/列表/详情页的组织，能设计 50+ 字段表单的可用方案）
│   ├── 流程与权限设计（角色-权限-数据范围矩阵、审批流引擎）
│   └── 报表与数据可视化（管理者视角的指标呈现）
├── L4 商业层
│   ├── 定价与商业模式（按量/按账号/私有化，能说清各自对产品设计的影响）
│   ├── 实施与客户成功（交付周期、二开与配置化的边界）
│    └── 私有化与定制管理（版本收敛策略）
```

## ⑤ 进阶检查点

| 阶段 | 能力证据（能做成这些即过关） |
|---|---|
| 初级（L1–L2） | 完成一次业务调研并输出流程全景图；为一条业务线撰写含异常流的完整 PRD |
| 中级（L3） | 设计复杂表单与权限体系的完整方案；从定制需求中抽象出平台化能力 |
| 高级（L4） | 主导一条 B端产品线的版本规划与交付节奏；设计私有化版本收敛策略 |

## ⑥ 常见误区

1. **用 C 端思路做 B 端**：追求极致体验忽视效率，B 端用户要的是"少点几次鼠标"。
2. **忽视实施与售后**：产品上线只是交付开始，实施成本与二开地狱是 B 端生死线。
3. **定制需求无管理**：来者不拒的定制会fork 出版本灾难，必须建立抽象与收敛机制。
4. **脱离业务流程谈功能**：不深入现场看懂业务流，做出来的系统只是把 Excel 搬上网。
5. **只做功能不做经营**：B 端产品最终要对客户的业务结果负责，数据价值呈现是必修课。
