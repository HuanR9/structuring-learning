# 产品数据分析细分模块

> 领域模块六节 Schema：领域画像 / 细分路由 / 预设知识骨架 / 权威信源清单 / 进阶检查点 / 常见误区。

## ① 领域画像

产品数据分析用数据发现问题、检验假设并支持决策：指标体系、埋点治理、异动归因、实验设计。核心价值是基于证据支持决策，同时说明数据质量、因果推断和适用范围的限制。

## ② 细分路由

本模块即最小细分单位，不再下分。重点是测量、分析和推断；渠道运营、触达策略与增长实验执行以 `growth.md` 为主，避免重复堆叠相同的增长方法。

## ③ 预设知识骨架

建模（P2）以此树为起点，按用户目标层级裁剪（规则见 `references/core/modeling.md`）。每个叶子节点括注掌握证据。

```
产品数据分析
├── L1 数据基础
│   ├── 指标体系（北极星指标/OSM/AARRR，能为一个产品搭指标树）
│   ├── 埋点设计（事件模型：事件-属性-用户，能设计一次改版的埋点方案）
│   └── SQL 与取数（多表关联/窗口函数/日期函数，能独立完成常规取数）
├── L2 分析方法
│   ├── 漏斗/留存/分群（漏斗定位流失环节、留存曲线判断产品价值；能用样例事件定义分母、窗口和分群条件，解释结果及数据缺口）
│   ├── 异动分析与归因（维度拆解、同期群、外部因素排除；能用样例数据按时间、用户和渠道拆解指标异动，交付驱动树并列出待排除的外部因素）
│   └── A/B 实验（假设提出、样本量计算、显著性与陷阱：多重比较/新奇效应；能写出可证伪假设、主指标与护栏指标，说明样本量依据、停止规则和多重比较风险）
├── L3 专题分析
│   ├── 用户画像（标签体系与使用边界；能定义一组可操作的用户标签，说明数据来源、更新规则、误用边界和验证方式）
│   ├── 增长分析（渠道质量、LTV/CAC；能按渠道计算转化与 LTV/CAC，注明归因窗口、成本口径和结论适用范围）
│   └── 预测与建模认知（回归/分类的使用场景与解释边界；能为一个预测问题选定朴素基线和评价指标，识别数据泄漏、偏差或解释性限制）
└── L4 数据产品与治理
    ├── 报表与看板设计（面向决策 vs 面向监控；能围绕一个具体决策设计看板结构，标明指标口径、更新频率、阈值含义和行动路径）
    └── 数据治理认知（指标口径统一、数据质量；能为一组业务指标建立口径字典和质量检查项，并用样例数据展示异常如何被发现）
```

## ⑤ 进阶检查点

| 阶段 | 能力证据（能做成这些即过关） |
|---|---|
| 初级（L1） | 搭出完整指标树；设计一份埋点方案并通过评审；独立完成常规取数与看板 |
| 中级（L2–L3） | 主导一次核心指标异动归因并给出可执行结论；设计并解读一次 A/B 实验（含样本量与显著性） |
| 高级（L4） | 建立指标口径与治理机制；用数据驱动一次真实的产品决策并被采纳 |

## ⑥ 常见误区

1. **指标堆砌无北极星**：看板几十个指标，没有一个是能指引决策的。
2. **相关当因果**：相关性不能直接归因为因果；实验或准实验之外，也可使用明确识别策略的观察性分析，但需说明假设、混杂因素和结论边界。
3. **A/B 不验样本量**：跑三天就"显著"，p 值操纵比不实验更危险。
4. **埋点混乱无治理**：事件名千人千面，数据可信度为零，分析从建地基开始。
5. **结论自嗨不落地**：分析报告没有指向产品动作，分析就没有完成闭环。
