# 数据合规细分模块

> 领域模块六节 Schema：领域画像 / 细分路由 / 预设知识骨架 / 权威信源清单 / 进阶检查点 / 常见误区。

## ① 领域画像

数据合规法务负责数据全生命周期的合法治理：收集、存储、使用、加工、传输、公开、删除各环节的义务落地。核心价值是**"让数据处理活动可证明地合法"**——合规的本质是可举证，不是口号。

## ② 细分路由

本模块即最小细分单位，不再下分。

## ③ 预设知识骨架

建模（P2）以此树为起点，按用户目标层级裁剪（规则见 `references/core/modeling.md`）。每个叶子节点括注掌握证据。全部法规与标准相关内容【时效敏感】，以现行有效版本为准。

```
数据合规
├── L1 法律基础层
│   ├── 三法框架（网安法/数安法/个保法的分工与联动，能画合规义务地图）
│   ├── 数据分类分级（重要数据识别、核心数据认知）
│   └── 个人信息处理规则（告知同意、最小必要、敏感信息特别规则）
├── L2 合规义务层
│   ├── 告知同意与隐私政策（合规文本的结构与红线，能审出违规点）
│   ├── 跨境传输（安全评估/标准合同/认证路径的选择）
│   └── 数据安全事件（应急预案、报告时限、处置流程）
├── L3 落地层
│   ├── PIA 个人信息保护影响评估（触发情形与报告结构）
│   ├── 合同条款（DPA 数据处理协议的关键条款设计）
│    └── 技术措施（脱敏/加密/访问权限/审计日志的合规映射）
└── L4 治理层
    ├── 合规体系与组织（制度+流程+培训的三位一体）
    └── 监管应对（检查清单、整改闭环）
```

## ⑤ 进阶检查点

| 阶段 | 能力证据（能做成这些即过关） |
|---|---|
| 初级（L1–L2） | 审查一份隐私政策/DPA 并指出违规点；为一次数据处理活动画合规义务清单 |
| 中级（L3） | 完成一份 PIA 报告；设计一个数据跨境场景的合规路径并给出理由 |
| 高级（L4） | 搭建企业数据合规体系；主导一次监管检查的应对与整改闭环 |

## ⑥ 常见误区

1. **套模板不理解三法**：三法各有分工，隐私政策模板抄来抄去，触发情形判断全错。
2. **忽视细则与行业规定**：金融、医疗、汽车、教育等行业有专门要求，通用模板覆盖不了。
3. **合规与技术两张皮**：制度写在纸上、数据裸奔在库里，没有技术措施映射的合规是纸面合规。
4. **拿过期法规**：法规标准更新频繁（配套细则、国家标准修订），去年答案今年可能就是错的。
5. **过度保守误伤业务**：把所有场景一刀切禁止，合规变成业务敌人；要会做风险分级与路径设计。
