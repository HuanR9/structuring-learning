# 动效设计细分模块

> 领域模块六节 Schema：领域画像 / 细分路由 / 预设知识骨架 / 权威信源清单 / 进阶检查点 / 常见误区。

## ① 领域画像

动效设计用有意义的运动提升界面体验：状态反馈、空间导航、情感愉悦。核心价值是**"让界面变化符合物理直觉与用户预期"**——动效不是装饰，是信息在时间维度上的组织方式。

## ② 细分路由

本模块即最小细分单位，不再下分。

## ③ 预设知识骨架

建模（P2）以此树为起点，按用户目标层级裁剪（规则见 `references/core/modeling.md`）。每个叶子节点括注掌握证据。

```
动效设计
├── L1 基础层
│   ├── 动画十二原则（迪士尼原则的界面化应用，能举例说明每条如何用于 UI）
│   ├── 时间/节奏/缓动（时长档位、easing 曲线选择，能说清一个动效的参数依据）
│   └── 动效的价值（反馈/引导/愉悦/转场，能论证动效解决了什么体验问题）
├── L2 工具层
│   ├── 原型动效工具（Principle/ProtoPie/Figma 动效面板）
│   ├── AE 与导出（After Effects + Lottie/Bodymovin 导出落地）
│   └── 代码动效认知（CSS transition/animation、Web Animations API 边界）
├── L3 交互动效
│   ├── 转场与页面流（共享元素、层级关系的空间表达）
│   ├── 微交互（按钮/加载/成功失败的细腻反馈设计）
│   └── 状态动效（空态/骨架屏/进度指示的设计）
└── L4 性能与落地
    ├── 性能预算（帧率、不掉帧的实现约束，能识别一个会掉帧的动效）
    └── 开发协作规范（参数交付、降级策略、 reduced motion 支持）
```

## ⑤ 进阶检查点

| 阶段 | 能力证据（能做成这些即过关） |
|---|---|
| 初级（L1–L2） | 设计并制作一套完整微交互（含参数说明）；用 Lottie 落地一个可运行的动效 |
| 中级（L3） | 设计一个 App 的完整转场体系（含共享元素）；与开发协作落地一次复杂动效 |
| 高级（L4） | 建立团队动效规范（时长/曲线/组件库动效）；用 A/B 或可用性测试证明动效价值 |

## ⑥ 常见误区

1. **为动而动**：动效增加了等待时间与视觉噪音，没有解决体验问题就是负资产。
2. **忽视平台规范**：iOS 与 Android 的导航与动效隐喻不同，跨平台照搬会违和。
3. **只做演示不落地**：原型里丝滑，开发实现不了或掉帧，等于没设计。
4. **忽视 reduced motion**：部分用户对动效敏感（前庭功能障碍），降级策略是必修项。
5. **参数凭感觉**：不按档位与曲线体系设计，动效之间风格割裂，团队无法复用。
