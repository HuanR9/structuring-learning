# UI/UX 设计细分模块

> 领域模块六节 Schema：领域画像 / 细分路由 / 预设知识骨架 / 权威信源清单 / 进阶检查点 / 常见误区。

## ① 领域画像

UI/UX 设计负责把产品方案落地为可用的界面与顺畅的体验：界面视觉（UI）与交互流程（UX）一体两面。核心价值是**"让用户不思考就能用对"**——降低认知成本优先于视觉炫技。

## ② 细分路由

本模块即最小细分单位，不再下分。视觉 / 动效 / 设计系统作为独立细分模块（见 `_index.md`），本模块聚焦通用界面与体验设计主线；这里只覆盖设计 Token、组件规范和动效交付的基础认知，体系治理与实现细节转到对应模块。

## ③ 预设知识骨架

建模（P2）以此树为起点，按用户目标层级裁剪（规则见 `references/core/modeling.md`）。每个叶子节点括注掌握证据。

```
UI/UX 设计
├── L1 视觉基础层
│   ├── 设计四原则（对比/对齐/重复/亲密性，能指出任意界面的违反点）
│   ├── 色彩（色相/明度/饱和度、配色套路、无障碍对比度标准；能为指定界面制定语义色板，检查文本与背景组合的可读性，并提交色彩使用和核验记录）
│   ├── 排版（字号阶梯、行高、字重层级，能排出清晰的阅读界面）
│   └── 栅格与间距（8pt 体系、栅格系统，能用统一间距体系布局）
├── L2 工具层
│   ├── 主力工具（Figma：组件/自动布局/变体，能高效搭建规范页面）
│   ├── 原型与交付（交互原型制作、设计标注与开发对接；能交付覆盖主流程、异常状态、关键尺寸和验收说明的原型或标注稿）
│   └── 素材与效率（图标库、插件生态、个人组件沉淀；能整理带来源与授权信息的素材清单，并将常用图标或样式沉淀为可复用资源）
├── L3 交互层
│   ├── 可用性原则（尼尔森十大原则，能做启发式评估）
│   ├── 交互模式（导航/表单/反馈/空状态等常见模式的选型；能按用户任务选择导航、表单或反馈模式，并用原型覆盖成功、空状态和错误分支）
│   ├── 用户流程设计（任务分析、流程图、异常分支覆盖；能画出目标用户完成一项任务的主路径、关键决策和失败恢复路径）
│   └── 信息架构（分类、层级、导航体系设计；能按用户任务组织内容层级，并用查找任务或分类反馈检查命名与归类）
├── L4 用户研究层
│   ├── 定性研究（用户访谈、可用性测试的设计与执行；能围绕一个研究问题拟定提纲或任务脚本，说明样本选择、记录方法和结论局限）
│   ├── 定量分析（埋点数据、漏斗、A/B 测试的解读边界；能从一组漏斗或实验数据定位变化，写出设计建议、关键假设与无法支持的因果结论）
│   └── 研究落地（把研究结论转化为设计决策并验证；能将一条研究发现连到设计改动和验证方式，并区分观察、解释与待证假设）
├── L5 体系层
│   ├── 设计系统（Design Token、组件库搭建与治理；能为一个界面指出可复用 Token/组件，并说明治理和实现细节应转到设计系统模块）
│   ├── 多端与适配（响应式、iOS/Android/Web 平台差异；能把同一任务流程适配到 Web 与移动端，交付差异对照和可验证的关键页面）
│   └── 无障碍设计（WCAG 基础、适老化；能按当前适用规范检查一个界面的键盘操作、语义和对比度，记录检查范围及未覆盖项）【时效敏感】
└── L6 协作与影响力（可选分支）
    ├── 设计评审（陈述方案、应对挑战的结构化表达；能在评审材料中说明用户问题、方案依据、约束和待决问题，并回应一项反对意见）
    └── 设计价值量化（用数据评估设计改动；能为一个设计改动选定前后指标与观察窗口，并说明混杂因素和不能据此断言的因果关系）
```

## ⑤ 进阶检查点

| 阶段 | 能力证据（能做成这些即过关） |
|---|---|
| 初级（L1–L2） | 拆解代表性界面并说明设计决策依据；用四原则诊断并改版一个存在可用性问题的界面 |
| 中级（L3–L4） | 独立设计一个完整功能流程（含异常态）并用启发式评估自查；组织小规模可用性测试，说明样本选择和结论局限并输出改进方案 |
| 高级（L5–L6） | 为中型产品搭建可落地的组件库与设计规范；用数据论证一次设计改版的收益 |

## ⑥ 常见误区

1. **视觉至上**：把 UI 当美工，忽视可用性与信息效率，好看但难用是失败设计。
2. **跳过用研拍脑袋**：不做用户研究直接出方案，设计决策全是个人偏好。
3. **工具收藏家**：Figma/Sketch/各种插件都摸一遍，不如一个工具用到精。
4. **忽视开发实现**：不了解前端实现成本与约束（如自动布局对应 flex），方案落地走样。
5. **只做单点不建体系**：每个页面单独设计，没有组件思维，规模一大就失控。
