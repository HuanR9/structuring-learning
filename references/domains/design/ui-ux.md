# UI/UX 设计细分模块

> 领域模块六节 Schema：领域画像 / 细分路由 / 预设知识骨架 / 权威信源清单 / 进阶检查点 / 常见误区。

## ① 领域画像

UI/UX 设计负责把产品方案落地为可用的界面与顺畅的体验：界面视觉（UI）与交互流程（UX）一体两面。核心价值是**"让用户不思考就能用对"**——降低认知成本优先于视觉炫技。

## ② 细分路由

本模块即最小细分单位，不再下分。视觉 / 动效 / 设计系统作为独立细分模块（见 `_index.md`），本模块聚焦通用界面与体验设计主线。

## ③ 预设知识骨架

建模（P2）以此树为起点，按用户目标层级裁剪（规则见 `references/core/modeling.md`）。每个叶子节点括注掌握证据。

```
UI/UX 设计
├── L1 视觉基础层
│   ├── 设计四原则（对比/对齐/重复/亲密性，能指出任意界面的违反点）
│   ├── 色彩（色相/明度/饱和度、配色套路、无障碍对比度标准）
│   ├── 排版（字号阶梯、行高、字重层级，能排出清晰的阅读界面）
│   └── 栅格与间距（8pt 体系、栅格系统，能用统一间距体系布局）
├── L2 工具层
│   ├── 主力工具（Figma：组件/自动布局/变体，能高效搭建规范页面）
│   ├── 原型与交付（交互原型制作、设计标注与开发对接）
│   └── 素材与效率（图标库、插件生态、个人组件沉淀）
├── L3 交互层
│   ├── 可用性原则（尼尔森十大原则，能做启发式评估）
│   ├── 交互模式（导航/表单/反馈/空状态等常见模式的选型）
│   ├── 用户流程设计（任务分析、流程图、异常分支覆盖）
│   └── 信息架构（分类、层级、导航体系设计）
├── L4 用户研究层
│   ├── 定性研究（用户访谈、可用性测试的设计与执行）
│   ├── 定量分析（埋点数据、漏斗、A/B 测试的解读边界）
│   └── 研究落地（把研究结论转化为设计决策并验证）
├── L5 体系层
│   ├── 设计系统（Design Token、组件库搭建与治理）
│   ├── 多端与适配（响应式、iOS/Android/Web 平台差异）
│   └── 无障碍设计（WCAG 基础、适老化）【时效敏感】
└── L6 协作与影响力（可选分支）
    ├── 设计评审（陈述方案、应对挑战的结构化表达）
    └── 设计价值量化（用数据证明设计改动的收益）
```

## ④ 权威信源清单

| 级别 | 信源 | 备注 |
|---|---|---|
| 官方规范 | Material Design / Apple Human Interface Guidelines | 平台规范基准【时效敏感】 |
| 官方规范 | Ant Design / TDesign 等中后台设计体系 | B端设计直接可参照 |
| 书籍 | 《写给大家看的设计书》 | L1 入门首选，四原则出处 |

| 社区 | NN/g（Nielsen Norman Group）、UX Collective | 用研与交互权威文章 |
| 实践 | 临摹优秀产品界面 + 反向拆解其设计决策 | 最有效的学习方式之一 |

## ⑤ 进阶检查点

| 阶段 | 能力证据（能做成这些即过关） |
|---|---|
| 初级（L1–L2） | 临摹三个优秀界面并说出每个设计决策的依据；用四原则诊断并改版一个糟糕界面 |
| 中级（L3–L4） | 独立设计一个完整功能流程（含异常态）并用启发式评估自查；组织一次 5 人可用性测试并输出改进方案 |
| 高级（L5–L6） | 为中型产品搭建可落地的组件库与设计规范；用数据论证一次设计改版的收益 |

## ⑥ 常见误区

1. **视觉至上**：把 UI 当美工，忽视可用性与信息效率，好看但难用是失败设计。
2. **跳过用研拍脑袋**：不做用户研究直接出方案，设计决策全是个人偏好。
3. **工具收藏家**：Figma/Sketch/各种插件都摸一遍，不如一个工具用到精。
4. **忽视开发实现**：不了解前端实现成本与约束（如自动布局对应 flex），方案落地走样。
5. **只做单点不建体系**：每个页面单独设计，没有组件思维，规模一大就失控。
